# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Запуск автотестов

```sh
node --test
```

Тесты находятся в `server.test.mjs` и проверяют успешную обработку заявки, валидацию некорректного ввода (`400 invalid_input`), а также перевод в `manual_review` при сбоях модели (`[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`).

## Что реализовано

1. **Серверная валидация и контракты (`server.mjs`):**
   - Проверка входящего JSON на `POST /api/triage`: при пустом, отсутствующем, нестроковом поле `text` или битом JSON возвращается HTTP `400` и `{"status":"invalid_input"}`.
   - Ограничение ожидания ответа модели до `300` мс через `AbortSignal.timeout(300)`.
   - Валидация ответа модели: парсинг JSON, проверка поля `topic` по белому списку (`delivery`, `pricing`, `other`) и проверка непустого строкового черновика `draft`.
   - При таймауте, ошибке провайдера или невалидном ответе модели возвращается HTTP `200` и `{"status":"manual_review","topic":null,"draft":null}`.
2. **Клиентский интерфейс (`index.html`):**
   - Отображение темы и черновика ответа при статусе `ready`.
   - Очистка предыдущего черновика и вывод понятного уведомления менеджеру при статусе `manual_review` или ошибке валидации.
   - Блокировка повторной отправки формы на время выполнения запроса.

## Ответы на вопросы

- **Где проверяется результат AI:** на сервере в `server.mjs` (`validateModelOutput`) сразу после получения ответа от `classify()` — до отправки данных клиенту.
- **Что происходит при сбое:** при таймауте (`300` мс), исключении провайдера или невалидном формате ответа сервер безопасно возвращает `{"status":"manual_review","topic":null,"draft":null}`, а интерфейс очищает предыдущий результат и сообщает менеджеру о необходимости ручного разбора.
- **Какой AI использовался:** использовался Gemini для анализа краевых случаев, ревью логики обработки ошибок и подготовки шаблона тестов на `node:test`; весь код проверен и доработан вручную.
- **Что проверено самостоятельно:** прогон автотестов и ручная проверка веб-интерфейса на `http://127.0.0.1:3000` на обычных заявках, пустом вводе и всех тестовых метках сбоя (`[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`).

## Польза для бизнеса

Решение ускоряет первичную обработку входящих заявок за счёт автоматической классификации и подготовки черновика ответа, переводя спорные или сбойные запросы на ручной разбор, что измеряется средним временем первого ответа клиенту и долей черновиков, принятых без переписывания.
